# Как запустить проект — пошаговая инструкция

Инструкция для новичка. Делайте шаги по порядку — каждый шаг зависит от предыдущего.
Итого у вас получится сайт с оплатой через ЮKassa, где купленные файлы
автоматически появляются у покупателя в личном кабинете.

---

## Что уже сделано за вас

В проекте уже настроено и готово к работе:

- 3 тарифа (300 ₽ / 900 ₽ / 1900 ₽) — цены берутся **только с сервера**, покупатель не может их подменить;
- вход и регистрация через email + пароль (Supabase Auth);
- страница «Мои покупки» (`/download`);
- приём вебхуков от ЮKassa с **проверкой платежа через API ЮKassa** (не доверяем тому, что прислали в вебхуке);
- выдача ссылки на скачивание только для оплаченных заказов, ссылка живёт 60 секунд;
- защита от подделки: даже зная ID заказа и подделав HTTP-ответ, файл не отдастся;
- `Dockerfile` и `docker-compose.yml` для размещения на сервере.

**Осталось сделать только 4 шага.** Это то, что нельзя сделать за вас:
завести учётные записи, загрузить файлы и указать ключи.

## Шаг 1. Получить ключи Supabase

Supabase — это база данных, где хранятся пользователи, заказы и файлы.

1. Откройте https://supabase.com и войдите в аккаунт.
2. Нажмите **New project**, придумайте имя и пароль базы (сохраните его — он больше не покажется).
3. Дождитесь создания проекта (1–2 минуты).

Теперь откройте **Project Settings → API** и скопируйте:

| Что копировать | Где найти | Куда вставлять в проекте |
|---|---|---|
| Project URL | Project Settings → API | `NEXT_PUBLIC_SUPABASE_URL` |
| anon public key | Project Settings → API → `anon public` | `NEXT_PUBLIC_SUPABASE_ANON_KEY` |
| service_role key | Project Settings → API → `service_role` | `SUPABASE_SERVICE_ROLE_KEY` |

> **Важно про ключи**
> - `anon public` — публичный ключ, он попадает в браузер. Это нормально, безопасность обеспечивают правила доступа (RLS).
> - `service_role` — **секретный ключ**. Он никогда не попадает в браузер и используется только на сервере. Храните его как пароль: если утечёт, злоумышленник сможет читать базу, минуя все ограничения.
> - В Supabase нажмите **Reveal** рядом с `service_role`, чтобы увидеть значение.
> - НИКОГДА не отправляйте этот ключ в чат, в мессенджер, не кладите в GitHub. Только в файл `.env.local` (шаг 4).

## Шаг 2. Получить ключи ЮKassa

ЮKassa — платёжный сервис.

1. Откройте https://yookassa.ru и зарегистрируйтесь (или войдите).
2. **Сначала работайте в тестовом режиме.** Он полностью бесплатный и не списывает реальные деньги.
   В личном кабинете ЮKassa есть переключатель «Тестовый режим» / «Боевой режим».
3. Откройте **Настройки → API-ключи** (в тестовом режиме — «Получить тестовые ключи»).
4. Скопируйте **Shop ID** (начинается на `test_` или цифры) и **Секретный ключ**.
5. Тестовые и боевые ключи — **разные**. Не смешивайте их. Если сайт работает в тестовом режиме,
   везде должны быть тестовые ключи.

> **Ключи YooKassa — тоже секрет.** Секретный ключ не должен попадать в браузер.
> Он используется только на сервере (файл `.env.local`).

### Чек обязателен (54-ФЗ) — иначе оплата не работает

Это самая частая причина «сайт не принимает оплату», и она неочевидна.

Если в кабинете ЮKassa включена **отправка чеков** (Настройки → Документы и чеки),
то запрос на создание платежа **без блока `receipt` отклоняется** с ошибкой
`400 Receipt is missing or illegal`. То есть деньги физически невозможно принять.

Проверено на боевом ключе: без чека — `400`, с чеком — платёж создаётся.

Поэтому код всегда отправляет чек (`lib/yookassa.ts`, функция `buildReceipt`):

- email покупателя — берётся из его аккаунта и подставляется в `receipt.customer.email`;
- ставка НДС — из переменной `YOOKASSA_VAT_CODE` (по умолчанию `3`, то есть без НДС);
- `payment_subject: "another"` и `payment_mode: "full_payment"` — именно эта пара
  проходит валидацию ЮKassa, другие значения она отклоняет.

**Если у вас ОСНО с НДС**, поставьте в `.env.local` → `YOOKASSA_VAT_CODE=1`.
Если вы самозанятый или работаете на УСН — оставьте `3`.

> Если email аккаунта вдруг пуст, сайт честно откажется с ошибкой `no_email`,
> а не создаст платёж без чека.

## Шаг 3. Создайте таблицу в базе данных

В проекте уже есть готовый SQL-файл: `supabase/migrations/0001_orders.sql`.
Он создаёт таблицу заказов, включает защиту (RLS) и создаёт приватное хранилище для файлов.

**Как применить:**

1. В Supabase откройте **SQL Editor** (иконка страницы с блокнотом в меню слева).
2. Нажмите **New query**.
3. Откройте файл `supabase/migrations/0001_orders.sql` у себя в редакторе кода,
   скопируйте **всё содержимое** и вставьте в SQL Editor.
4. Нажмите **Run** (или `Ctrl+Enter`).
5. Если увидите `Success — no rows returned` или зелёную галочку, всё готово.

**Проверьте, что всё создалось:**

1. В Supabase откройте **Table Editor** → должна появиться таблица `orders`.
2. Откройте **Storage** → в списке должен быть бакет `paid-files`.
3. Откройте бакет `paid-files` → **Policies** → убедитесь, что есть политики только чтения для
   `authenticated` (чтобы файлы не были публичными) и что нет публичной политики на SELECT для всех.

> Если SQL выполнился с ошибкой «already exists» — это нормально, значит часть объектов уже создана.
> Перечитайте сообщение об ошибке: обычно достаточно просто перезапустить выполнение.

## Шаг 4. Загрузите сами файлы (ZIP)

Это то, что продаётся. Файлы лежат **приватно**, доступ выдаётся только после оплаты.

1. Подготовьте три ZIP-файла (если их ещё нет):
   - `gameland-start.zip`
   - `gameland-pro.zip`
   - `gameland-ultimate.zip`
2. В Supabase откройте **Storage** → бакет `paid-files`.
3. Нажмите **Upload files** и загрузите `gameland-start.zip` в папку `products/start/`.
   То есть итоговый путь должен быть: `products/start/gameland-start.zip`.

   Повторите для остальных:
   - `products/pro/gameland-pro.zip`
   - `products/ultimate/gameland-ultimate.zip`

> **Точные пути важны.** Путь файла прописан в коде (`lib/products.ts`). Если назвать файл иначе,
> покупатель оплатит, но не сможет скачать. Внимательно проверьте путь после загрузки —
> он должен совпадать символ в символ (регистр букв тоже важен).
>
> Как создать папку при загрузке: в окне загрузки можно указать путь с папкой,
> либо сначала создать папку кнопкой **New folder**.

### Ограничения на файл (настраиваются в SQL)

По умолчанию бакет принимает **любые типы файлов**, но не больше **500 МБ** на файл.
Если нужны ограничения по расширению (например, только `.zip`), поправьте
`allowed_mime_types` в `supabase/migrations/0001_orders.sql` и выполните SQL заново.

## Шаг 5. Настройте файл с ключами

1. В папке проекта есть файл-образец **`.env.example`**.
2. Создайте рядом новый файл **`.env.local`** (именно `.env.local`, не `.env.example`).
   - Windows: скопируйте `.env.example` → переименуйте в `.env.local`.
   - Если не видно файлов с точкой — в Проводнике: «Вид» → «Расширения имён файлов».
3. Заполните значения:

```bash
# Supabase — из шага 1
NEXT_PUBLIC_SUPABASE_URL=https://ваш-проект.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJhbGciOi...
SUPABASE_SERVICE_ROLE_KEY=eyJhbGciOi...

# ЮKassa — из шага 2 (тестовые ключи для тестового режима)
YOOKASSA_SHOP_ID=123456
YOOKASSA_SECRET_KEY=test_XXXX
# Ставка НДС в чеке: 1 = 20%, 3 = без НДС (для самозанятых/УСН)
YOOKASSA_VAT_CODE=3

# Адрес сайта. Пока локально — http://localhost:3000
NEXT_PUBLIC_BASE_URL=http://localhost:3000
```

> Сохраняйте файл в кодировке **UTF-8 без BOM** (обычный «Сохранить» в блокноте — ок).

## Шаг 7. Приём вебхуков в ЮKassa (обязательно!)

Без этого покупатель оплатит, но файл не откроется: сайт не узнает об оплате.

Вебхук — это «звонок» от ЮKassa на ваш сайт: «платёж прошёл».

> **Это можно настроить только когда у сайта есть публичный HTTPS-адрес** (шаг 8).
> Локально (localhost) ЮKassa до вас не достучится.

**Как настроить (после деплоя из шага 8):**

1. В личном кабинете ЮKassa откройте **Настройки → Уведомления** (или «Webhook»).
2. В поле адреса укажите:

```
https://ваш-домен.ru/api/webhooks/yookassa
```

3. Включите события:
   - `payment.succeeded` (платёж прошёл) — **обязательно**
   - `payment.canceled` (отменён) — **желательно**
4. Сохраните и включите уведомления.

**Проверка, что вебхук работает:**

1. Сделайте тестовую покупку на сайте (тестовый режим).
2. В ЮKassa откройте платёж → вкладка **«Операции»** → там будет запись о доставке уведомления.
   Статус должен быть «успешно доставлено».
3. У себя в Supabase откройте **Table Editor → orders**: у заказа должен быть статус `succeeded`.

Если уведомление не доставлено, проверьте:
- адрес написан полностью и без опечаток;
- сайт открыт по HTTPS;
- в логах сервера нет ошибок (см. шаг 8).

> **Про проверку IP.** Код дополнительно проверяет, что запрос пришёл с IP-адреса ЮKassa.
> Если сайт стоит за nginx, нужно передавать реальный IP (см. шаг 8).
> Это дополнение к основной проверке: платёж всё равно перепроверяется через API ЮKassa,
> поэтому даже при неверном IP безопасность не нарушается — платёж просто может не обновиться автоматически.
> В `.env.local` можно добавить `YOOKASSA_WEBHOOK_IP_CHECK=0`, чтобы отключить проверку IP,
> если вы не уверены в настройке прокси.

## Шаг 8. Размещение на сервере (VPS + Docker)

Подойдёт любой VPS: Timeweb, Beget, Selectel, Aéza, Hetzner — с Ubuntu 22.04/24.04.
Требования: 1 CPU, 1 ГБ RAM, 20 ГБ диска, и **домен** (обязательно для HTTPS).

### 8.1. Подготовьте сервер

```bash
ssh root@ваш-ip-сервера
apt update && apt upgrade -y
```

### 8.2. Установите Docker

```bash
curl -fsSL https://get.docker.com -o get-docker.sh
sh get-docker.sh
systemctl enable --now docker
docker --version   # убедитесь, что версия вывелась
```

### 8.3. Загрузите проект на сервер

Скопируйте папку проекта на сервер. Удобно через Git:

```bash
# На сервере:
apt install -y git
git clone <адрес-вашего-репозитория> /opt/gameland
cd /opt/gameland
```

(Если репозитория нет — залейте файлы любым способом, например через `scp` или FileZilla.)

### 8.4. Создайте файл с ключами на сервере

```bash
nano /opt/gameland/.env
```

Впишите **боевые** значения (для боевого режима нужны боевые ключи ЮKassa!):

```bash
NEXT_PUBLIC_SUPABASE_URL=https://ваш-проект.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJhbGciOi...
SUPABASE_SERVICE_ROLE_KEY=eyJhbGciOi...
YOOKASSA_SHOP_ID=123456
YOOKASSA_SECRET_KEY=live_XXXX
YOOKASSA_VAT_CODE=3
NEXT_PUBLIC_BASE_URL=https://ваш-домен.ru
```

> Внимание: `NEXT_PUBLIC_BASE_URL` тут — адрес сайта (https://ваш-домен.ru), а не хостинг.
> Именно на этот адрес ЮKassa будет слать вебхуки из шага 7.

> **Важно про NEXT_PUBLIC_*:** эти значения «зашиваются» в код на этапе сборки.
> Поэтому при смене адреса или ключей нужно **пересобрать** образ (см. следующий шаг).

### 8.5. Запуск

```bash
cd /opt/gameland
docker compose up -d --build
docker compose logs -f app    # смотреть логи
```

Проверьте: `curl http://localhost:3000/api/health` → `"ok": true`.

> Сборка образа занимает 3–7 минут (качает зависимости). Это нормально.

## Шаг 9. Домен и HTTPS (nginx)

### 9.1. Направьте домен на сервер

В панели управления доменом (или у регистратора) добавьте **A-записи**:

```
Тип: A     Имя: @     Значение: IP-вашего-сервера
Тип: A     Имя: www   Значение: IP-вашего-сервера
```

Подождите 5–30 минут, пока изменения применятся. Проверить можно командой
(замените домен на свой):

```bash
nslookup ваш-домен.ru
```

В ответе должен быть IP вашего сервера.

### 9.2. Установите nginx и сертификат

```bash
apt install -y nginx certbot python3-certbot-nginx
```

Создайте конфиг сайта:

```bash
nano /etc/nginx/sites-available/gameland
```

Вставьте (заменив `ваш-домен.ru` на ваш домен):

```nginx
server {
    listen 80;
    server_name ваш-домен.ru www.ваш-домен.ru;

    # ВАЖНО для проверки IP в вебхуке: передаём nginx реальный IP клиента,
    # чтобы сайт видел адрес ЮKassa, а не адрес прокси.
    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Upgrade           $http_upgrade;
        proxy_set_header Connection        "upgrade";
        proxy_read_timeout 60s;
    }
}
```

Включите сайт и получите сертификат HTTPS (бесплатно):

```bash
ln -s /etc/nginx/sites-available/gameland /etc/nginx/sites-enabled/
nginx -t && systemctl reload nginx
certbot --nginx -d ваш-домен.ru -d www.ваш-домен.ru --agree-tos -m ваша@почта.ru
```

Certbot сам перенастроит nginx на редирект с HTTP на HTTPS и добавит автопродление
сертификата (проверить: `certbot renew --dry-run`).

Проверьте: открывается https://ваш-домен.ru

> **Что делает nginx:** принимает запросы посетителей по HTTPS, и передаёт их приложению
> внутри сервера по обычному HTTP. Приложение слушает порт 3000 и наружу его не открывает.

## Шаг 10. Финальная проверка (что должна пройти каждая проверка)

Пройдите все пункты. Это финальный «чеклист» перед приёмом денег от покупателей.

**Безопасность (главное):**

- [ ] `curl http://localhost:3000/api/health` возвращает `"ok": true`
- [ ] Открыть `/download` без входа → происходит переход на страницу входа
- [ ] Зайти в систему → `/download` показывает «У вас пока нет покупок»
- [ ] Войти под другим пользователем → покупок не видно
- [ ] Попробовать открыть ссылку на файл повторно через 2 минуты → срок истёк
- [ ] **Главная проверка:** залогиниться, купить тариф, затем с другого браузера (другой
      пользователь) попробовать открыть ссылку на файл → **доступа нет**
- [ ] Файл не лежит по прямой ссылке `https://ваш-домен.ru/products/...` → отдаётся ошибка

**Оплата (только в тестовом режиме ЮKassa):**

- [ ] На странице `/` есть блок с тарифами, у каждого — кнопка «Купить»
- [ ] Нажать «Купить» → открывается страница оплаты ЮKassa с **верной** суммой
      - Если вместо этого ошибка `Receipt is missing or illegal` → проверьте чек в шаге 2
      - Если ошибка `Error in shopId or secret key` → в `.env` лежит старый ключ,
        а в кабинете уже перевыпущенный. Скопируйте ключ заново (и пересоберите образ).
- [ ] Проверить подмену суммы: в браузере изменить цену и отправить запрос вручную →
      сервер всё равно создаёт платёж с правильной ценой
- [ ] Оплатить тестовой картой → страница «Мои покупки» показывает файл
- [ ] Скачать файл → ZIP открывается и работает
- [ ] Не оплачивать, нажать «Отменить» → статус заказа становится `canceled`, доступа нет
- [ ] Потерянный вебхук: оплатить, не обновлять страницу, потом нажать
      «Обновить статус оплаты» → файл появляется (проверка «страховки»)
- [ ] В Supabase → таблица `orders` — записи со статусом `succeeded`

**Перед приёмом реальных денег:**

- [ ] Переключить ключи ЮKassa на **боевые** (и пересобрать образ!)
- [ ] `YOOKASSA_VAT_CODE` соответствует вашему налоговому режиму
      (`1` = НДС 20%, `3` = без НДС для самозанятого/УСН)
- [ ] Проверить, что `NEXT_PUBLIC_BASE_URL` содержит именно `https://ваш-домен.ru`
- [ ] Вебхук настроен на боевой адрес и доставляется успешно
- [ ] Сделать одну реальную покупку на минимальную сумму и проверить всё end-to-end
- [ ] Проверить, что `.env` НЕ попадает в Git (см. шаг 11)

## Шаг 11. Не залейте секреты в Git

Файл `.env` (с ключами) содержит **секретный ключ Supabase**. Если он попадёт в публичный
Git-репозиторий, его утечку не отменить.

В проекте уже настроено: файл `.env` добавлен в `.gitignore`, а `.env.example` — нет
(это шаблон без секретов, его коммитить можно и нужно).

Проверьте перед коммитом:

```bash
git status          # .env не должен тут появляться
git ls-files | grep env
```

Если `.env` уже попал в историю Git — **смените ключи в Supabase** (Настройки → API →
перевыпустить service_role) и удалите файл из истории.

## Частые проблемы

**`"ok": false` и список `missingEnvVars`**
Не хватает переменных окружения. Проверьте `.env.local`: есть ли все названия из списка,
нет ли лишних пробелов, не забыт ли перезапуск сервера после правки (`npm start` заново).

**При переходе на сайт вместо приложения / белый экран**
Обычно приложение упало. Смотрите логи: `docker compose logs -f app`.

**Покупка прошла, но файл не появился**
1. Не настроен вебхук (шаг 7) — самая частая причина.
2. Проверьте в Supabase таблицу `orders`: если статус остался `pending`,
   вебхук не дошёл. Смотрите логи сервера — там будет причина.
3. Файл лежит не по тому пути (шаг 4).
4. Кнопка «Обновить статус оплаты» на странице покупок перезапрашивает статус
   у ЮKassa вручную — если после неё файл появился, дело точно в вебхуке.

**`invalid claim: missing sub claim` / ошибки авторизации**
Ключи Supabase от разных проектов. Проверьте, что `SUPABASE_SERVICE_ROLE_KEY`
и `NEXT_PUBLIC_SUPABASE_ANON_KEY` из **одного** проекта.

**Ошибка при сборке Docker**
`npm ci` требует, чтобы `package-lock.json` совпадал с `package.json`. Выполните
локально `npm install`, затем `git commit` оба файла и повторите сборку.

**Порт 3000 занят**
`docker compose down && docker compose up -d`. Или смените порт в `docker-compose.yml`.

## Шпаргалка команд

```bash
# Локально
npm install                                  # установить зависимости
npm run build                                # собрать
npm start                                    # запустить
npm run lint                                 # проверить код

# На сервере
docker compose up -d --build                 # собрать и запустить
docker compose logs -f app                   # логи
docker compose restart app                   # перезапустить
docker compose down                          # остановить

# Боевые ключи/адрес поменял -> обязательно пересборка:
docker compose up -d --build
```
